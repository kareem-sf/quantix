# Task 2 implementation report

## Summary

Replaced Task 1's temporary `{ code, pointer }` validation shape with the public Rust/TypeScript `OutputValidationIssue { code, path, message }` and a single deterministic Tender Record validation report. Reports are path/code sorted and retain at most 64 issues.

`TenderStore::validate_tender_record_proposal` is now the single provider-output entry point. It returns a two-layer result: the outer `Result` preserves database, authority-loading, I/O, and integrity `TenderCommandError`s; the inner result distinguishes provider-shaped semantic defects as `TenderRecordValidationReport`. This corrects the illustrative flat signature because it could not represent both required error classes. The completion boundary retains semantic issues on the output-invalid failure for Task 3's rejected-output transaction.

The new parity test covers duplicate stable keys, blank/UTF-8-overlong titles, duplicate fields and evidence, evidence-basis metadata schema rejection, authoring format, deadline parsing, contradiction evidence, and foreign-authority schema rejection. Semantic cases assert exact code/path/message; structurally impossible payloads assert strict-schema rejection.

## Design decisions

- Stable messages contain no Tender content, source text, or secrets.
- The report keeps the lexicographically earliest 64 `(path, code)` issues, independent of discovery order.
- Strict output-schema failures remain schema failures rather than fabricated semantic reports.
- The generic legacy canonical validator remains as a final guard; provider-invalid outcomes are converted to one stable `invalid_record` report while non-`InvalidCommand` failures continue through the outer infrastructure error channel.

## Known risks

- The legacy canonical final guard has broader historical-validation coverage than the new semantic collector. Its residual provider-invalid branch currently reports the stable generic `invalid_record` issue; further parity cases should be added when new cross-field domain rules are introduced.
