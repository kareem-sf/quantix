# Adaptive Quantix Health and Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the existing Quantix Doctor a truthful, typed health aggregate that isolates failed capabilities, runs only proven reversible operational repairs, and routes every canonical recovery decision to its owning Engineer-reviewed Tender command.

**Architecture:** Keep `doctor.rs` as the one public aggregate and compose it from a read-only Host-owned preflight snapshot. Add a closed readiness/finding/repair vocabulary there; the Tauri command validates the current report revision, executes one named Host allowlist, and re-inspects. Safe operational mutations remain in their present diagnostics, application-settings, Host-startup, and Tender Store owners; profile activation, Agent Run disposition, Tender recovery, AI selection, approvals, provenance, and history changes are returned only as typed Engineer review routes and are never dispatched by Doctor.

**Tech Stack:** Rust 2021, Tauri 2 IPC, Serde with `deny_unknown_fields`, `ts-rs` generated TypeScript bindings, SQLite/Rusqlite, Tokio, Vitest/TypeScript consumers in the subsequent resilient-production-UX slice.

**Spec:** `docs/superpowers/specs/2026-08-21-adaptive-quantix-doctor-design.md`

## Global Constraints

- Do not add a parallel health framework; extend `src-tauri/src/doctor.rs`, diagnostics, Tender recovery, and startup-reconciliation boundaries.
- `ReadinessState` is exactly `ready | healing | review_required | blocked | unavailable_external`.
- The public aggregate is exactly `QuantixDoctorReport { revision, readiness_state: ReadinessState, findings, automatic_actions: Vec<AutomaticRepairResult> }`; remove the obsolete `healthy` field without an adapter, fallback, migration, or dual presentation path.
- Every `QuantixDoctorFinding` includes a stable `code`, correlation ID, application-or-Tender scope, capability, severity, `readiness_state`, redacted cause facts, impact, data-change fact, action history, safe remediation, exact review route when present, retry safety, and timestamps. The renderer failure code is exactly `renderer_surface_unavailable`.
- Startup and Tender-open preflight are read-only. Re-run command-time preflight immediately before a side-effecting command; block only the command’s required capability.
- The only Doctor mutation command is `run_safe_repairs`; it runs a closed allowlist of reversible, idempotent, non-canonical actions with bounded resources and reinspection. It must never change Tender Audit Event count, approval, provenance, authority, provider/model selection, profile version/history, Tender facts, recovery disposition, update installation state, credentials, Trash, or data-bearing/uncertain workspace state.
- All canonical changes remain in existing domain-owned Engineer commands, including `ResolveIndeterminateAgentRunCommand`, Tender integrity recovery, Tender AI selection/rebinding, and the contract slice’s profile-revision activation command. Doctor returns routes to those commands; it never calls them.
- A possibly accepted provider Turn is never replayed. `OutcomeUnknown` and `Indeterminate` remain Engineer-reviewed; Doctor reports their exact recovery route and no local automatic repair.
- Findings and automatic results are local, redacted, bounded, and contain no Tender content, prompts, responses, credentials, raw provider traffic, arbitrary paths, stack frames, or hidden reasoning.
- Keep `src/bindings` generated by Rust/`ts-rs` tests and committed. Do not edit generated declarations manually. This plan makes the minimum renderer fixture/consumer changes needed to keep the repository compiling when `healthy` is removed; the resilient-production-UX plan owns the richer indicator and the content-free renderer diagnostic receipt return.
- Do not run production builds during this plan. The final repository gate is deferred until the dependent contract, metadata, and UX slices compile together.

## File Structure

- `src-tauri/src/doctor.rs` — closed public Doctor DTOs, readiness reduction, redacted typed finding composition, safe-action eligibility, and stale-report validation.
- `src-tauri/src/health_preflight.rs` — read-only application/Tender capability snapshots and the mapping of runtime, Tender integrity, Agent Run, provider, diagnostics, and renderer facts into Doctor inputs.
- `src-tauri/src/host.rs` — one bounded Host safe-repair coordinator and startup/Tender-open preflight entry points; it calls named owner functions only.
- `src-tauri/src/tender_store.rs` — safe inspection/reconciliation of verified non-canonical staging and derived installation catalogue; it rejects any data-bearing or uncertain residual.
- `src-tauri/src/tender_store/agent_records.rs` — read-only Agent Run failure facts for preflight; existing `reconcile_interrupted_agent_runs` remains the authority that preserves uncertainty as `Indeterminate`.
- `src-tauri/src/lib.rs` — thin Tauri command composition, one `run_safe_repairs` dispatch, and `ts-rs` export coverage; command-owner gateways in Host, Agent Runtime, Document Parsing, and Tender Store enforce immediate preflight for IPC and non-IPC callers alike.
- `src-tauri/src/diagnostics.rs` — one bounded diagnostic-writer restart/retention safe action and its deterministic health result.
- `src/bindings/*.ts` — generated public declarations only; Task 1 performs the minimum compile-preserving renderer adaptation, and the later UX slice replaces it with the production presentation.

```rust
impl QuantixDoctorReport {
    pub fn from_findings(
        findings: Vec<QuantixDoctorFinding>,
        automatic_actions: Vec<AutomaticRepairResult>,
    ) -> Self {
        let readiness_state = findings
            .iter()
            .map(|finding| finding.readiness_state)
            .max_by_key(|state| match state {
                ReadinessState::Ready => 0,
                ReadinessState::Healing => 1,
                ReadinessState::UnavailableExternal => 2,
                ReadinessState::ReviewRequired => 3,
                ReadinessState::Blocked => 4,
            })
            .unwrap_or(ReadinessState::Ready);
        let revision = report_revision(&findings, &automatic_actions, readiness_state);
        Self { revision, readiness_state, findings, automatic_actions }
    }
}

impl QuantixDoctorFinding {
    fn blocked_application(
        code: &str,
        capability: Capability,
        title: &str,
        cause: &str,
```

```rust
pub fn compose_preflight_findings(
    application: &[CapabilityPreflight],
    tender: Option<&TenderHealthFacts>,
) -> Vec<QuantixDoctorFinding> {
    let mut findings = application
        .iter()
        .filter_map(finding_from_preflight)
        .collect::<Vec<_>>();
    if let Some(tender) = tender {
        if tender.integrity.state != TenderIntegrityState::Ready {
            findings.push(QuantixDoctorFinding::tender_review(
                "tender_integrity_not_ready", &tender.tender_id, "Tender Store integrity",
                "The Tender Store did not pass its integrity inspection.",
                "This Tender is isolated; other Tenders remain available.",
                EngineerReviewRoute::InspectTenderIntegrity,
            ));
        }
        findings.extend(tender.agent_run_findings.clone());
    }
    findings
}
```

```rust
        }
    }
    Ok(())
}
```
