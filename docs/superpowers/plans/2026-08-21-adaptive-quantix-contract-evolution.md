# Adaptive Quantix Contract Evolution Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Rust-owned contract registry and committed manifest that rejects undeclared contract changes, reports existing-Tender contract drift truthfully, and activates a declared new profile/output-contract revision only through an Engineer-reviewed immutable append.

**Architecture:** `contract_registry.rs` derives canonical contract payloads from every deterministic system-profile/output-contract factory used by Agent preparation—including Tender Record extraction/review—the provider schema, Tender schema, and exported IPC definitions. A committed `src-tauri/contract-manifest.json` contains only stable keys, families, revisions, fingerprints, affected capabilities, and activation policies; release verification compares it with the Rust registry. Tender preflight compares registry definitions and their declared historical revisions with immutable `agent_profile_versions`; a declared successor is `review_required`, a changed or undeclared same-revision definition is `contract_drift`, and the only canonical recovery is the direct Engineer command that appends a new profile version, advances its head, and records an Audit Event.

**Tech Stack:** Rust 2021, Tauri 2 IPC, `serde`/`serde_json_canonicalizer`, SHA-256, SQLite/Rusqlite, `ts-rs` generated TypeScript bindings, Cargo tests, deterministic Product Acceptance release gates.

**Spec:** `docs/superpowers/specs/2026-08-21-adaptive-quantix-doctor-design.md`

## Global Constraints

- Strict boundaries, dynamic domain content. IPC, security, authority, and persisted envelope contracts remain strict.
- Prevent before repairing. Verification rejects undeclared contract changes. Doctor is the production safety net, not a substitute for release correctness.
- No silent canonical mutation. Automatic repair is limited to reversible, idempotent, non-canonical operational state.
- Engineer-in-the-Loop recovery. Any action that changes a Tender Store, immutable history, provenance, approval, provider selection, or recovery disposition requires an attributable Tendering Engineer command.
- No silent replay or fallback. Quantix never repeats a possibly accepted provider Turn, substitutes a provider/model, or infers missing metadata.
- Contract Registry is Rust-owned. The committed generated manifest contains `(key, family, revision, sha256, affected_capabilities, activation)` and contains no Tender content.
- The registry covers the system contracts used by every existing `prepare_*_run` gateway. At minimum it includes the four bootstrap roles, Manager intake, Tender Record extraction version 4, Tender Record review version 3, and every other deterministic calculation, pricing, bid-package, and submission-review output schema. A completeness test fails when a new system Agent work kind has no declared keys.
- A `(key, revision)` has exactly one digest; changing a digest without advancing the revision fails before release.
- New Tender creation seeds current system profile/output-contract definitions through the existing explicit `CreateTenderCommand` transaction.
- Existing Tender activation appends a new immutable `agent_profile_versions` row, advances only the relevant `agent_profile_heads` row, and appends one immutable Audit Event; it never rewrites version 1, prior tasks, runs, provider threads, or exposure sets.
- `contract_drift` never overwrites persisted or registry definitions; it blocks only dependent future work and offers no activation repair action.
- Do not add a general database migration framework, compatibility DTOs, fallback parsers, dual storage paths, autonomous Tender Store repair, or automatic provider/model selection.
- Strict Serde `deny_unknown_fields` remains on commands and fixed envelopes.
- Generated declarations under `src/bindings` are committed and regenerated by Rust/`ts-rs`; never edit them manually.
- Production builds remain explicit release-stage operations; normal development ends with formatting, checks, deterministic tests, and `npm run verify`.

- [ ] **Step 4: Implement manifest validation against the Rust source.** Require the input already be sorted by `(key, revision)`, reject duplicate/out-of-order tuples, require every current key/revision exactly once, reject every extra tuple, compare every digest to the digest computed from its Rust canonical payload, and compare `family`, `affected_capabilities`, and `activation` exactly:

```rust
pub fn validate_manifest_against_registry(source: &str) -> Result<(), ContractRegistryError> {
    let manifest: ContractManifest =
        serde_json::from_str(source).map_err(|_| ContractRegistryError::ManifestEncoding)?;
    let current = current_contract_manifest();
    for (left, right) in manifest.entries.iter().zip(manifest.entries.iter().skip(1)) {
        if (left.key.as_str(), left.revision) >= (right.key.as_str(), right.revision) {
            return Err(ContractRegistryError::DuplicateKeyRevision);
        }
    }
    for expected in &current.entries {
        let actual = manifest
            .entries
            .iter()
            .find(|entry| entry.key == expected.key && entry.revision == expected.revision)
            .ok_or_else(|| ContractRegistryError::MissingCurrentContract {
                key: expected.key.clone(),
            })?;
        if actual.sha256 != expected.sha256 {
            return Err(ContractRegistryError::FingerprintChanged {
                key: expected.key.clone(),
                revision: expected.revision,
            });
        }
        if actual.family != expected.family
            || actual.affected_capabilities != expected.affected_capabilities
            || actual.activation != expected.activation
        {
            return Err(ContractRegistryError::ManifestMetadataChanged {
                key: expected.key.clone(),
                revision: expected.revision,
            });
        }
    }
    if let Some(extra) = manifest.entries.iter().find(|entry| {
        !current.entries.iter().any(|expected| {
            expected.key == entry.key && expected.revision == entry.revision
        })
    }) {
        return Err(ContractRegistryError::UnexpectedContract {
            key: extra.key.clone(),
            revision: extra.revision,
        });
    }
    Ok(())
}
```
