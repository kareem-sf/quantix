# Qualify v0 through layered product acceptance

Status: accepted on 2026-08-07 by explicit Engineer User confirmation.

Quantix qualifies releases through two cumulative product gates rather than treating a successful build, polished AI output, or one demonstration as acceptance. Private v0 Qualification proves an engineer-operated Windows release candidate against deterministic checks, the original bilingual Acceptance Tender Fixture, repeated live Codex runs, and a packaged end-to-end rehearsal. Public Release Gate adds native packaged qualification on every supported platform and blocks distribution until the Codex integration has production assurance and terms permitting the intended third-party subscription-backed use.

## Consequences

- One fully synthetic bilingual Egyptian employer-designed building Tender, synthetic contractor library, and machine-readable Acceptance Oracle remain the public golden fixture. Authentic FIDIC text and real-company material remain in a separate private licensed calibration lane.
- Every pull request runs deterministic domain, calculation, document, evidence, permission, prompt-injection, file-security, storage, recovery, provider-contract, artifact, UI, and regression checks without requiring a live account. A deterministic fake app-server drives protocol, interruption, malformed-message, crash, restart, and indeterminate-turn cases on Windows, macOS, and Linux CI.
- A release candidate must complete five consecutive clean live runs against the pinned Codex version. Every run must recover 100% of oracle-marked critical requirements, addenda, deadlines, forms, and submission instructions; introduce zero unsupported critical requirements; account for 100% of BOQ rows; reproduce 100% of deterministic calculations; attach an approved provenance class to 100% of material claims; and recall at least 95% of non-critical oracle items.
- No averaging can hide a critical, calculation, evidence, permission, EITL, information-boundary, prompt-injection, integrity, recovery, or security failure. Any such failure blocks qualification. Tender package Critical Review Findings remain non-waivable; permitted Major findings require exact EITL Exception Approval, and disclosed Minor findings may remain only through Final Approval.
- Private v0 Qualification requires the full native packaged lifecycle on Windows 11 x64 with an opted-in Engineer User's existing ChatGPT-authenticated Codex session. It is explicitly non-public and makes no production-support claim.
- Public Release Gate requires the same signed-package acceptance on Windows 11 x64, macOS 14+ Apple Silicon, and Ubuntu 24.04 x64. Native CI runs the deterministic suite on all three; a private real-login Codex smoke test and native accessibility, updater, installation, import, processing, recovery, export, and uninstall checks must pass on each target before support is claimed.
- Product acceptance enforces versioned Safety Limits, timeouts, bounded resources, free-disk checks, no hangs, no orphaned child processes, and no partial canonical publication. v0 records processing time by stage but invents no latency SLA before a complete fixture establishes a measured baseline; later releases may set regression limits from that evidence.
- The repository exposes one deterministic verification entry point, one opted-in live-provider evaluation entry point, one native packaging-validation entry point, and one release-acceptance entry point. Their exact command syntax is fixed when the workspace is scaffolded and then recorded in `AGENTS.md`; one command cannot conceal which gate failed.
- Each qualifying attempt emits immutable Product Acceptance Runs. An attributable Product Acceptance Record binds exact fixture, oracle, source, application, Codex, Docling, model, schema, binary, dependency, platform, test, evaluation, package, finding, exception, metric, timing, and artifact hashes for the release candidate.
- App-server and provider-thread state are never acceptance evidence by themselves. Canonical product assertions come from Quantix-owned records and reproducible outputs; credentials and raw provider reasoning never enter the Product Acceptance Record.
- Technical acceptance of an experimental app-server version may support a private v0. It cannot authorize public distribution where product support or applicable service terms remain unresolved; that requires OpenAI assurance or a separately approved provider architecture.
