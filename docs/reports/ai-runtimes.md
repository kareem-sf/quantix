# Local AI clients

Implementation date: 7 September 2026. These changes have not been exercised against live accounts. No tests, lint, typechecks, browser checks or integration checks were run, in accordance with the current engineer instruction.

## Boundaries

`ai_runtimes.execute_runtime` has the same inputs and result envelope as the model API adapter. It adds the office's engineering instructions, runs an original client, and returns a validated proposal, usage and consulted web sources. It does not publish findings, approve quantities or prices, create commercial authority, or send supplier messages.

`ai_runtime_mcp.RuntimeToolBridge` uses the installed MCP 2.1.1 server implementation. Each execution gets a separate loopback socket, random bearer token and closed set of Quantix tools. Requests with browser origins or without the token are rejected. Tool calls are serialized against the active OfficeContext, use the existing Pydantic argument validation, and stop when the run is no longer active. Images remain native MCP image blocks. Drawing inspection fails explicitly when the chosen model's image support has not been established.

The additional `quantix_submit_result` MCP tool accepts the complete output schema and validates it locally. It stages an in-memory proposal; it does not approve or publish anything. Chat text is not scraped for JSON. All adapters require a successful original-client terminal outcome as well as a valid submitted proposal.

Client configuration and working directories are under `repo.home/ai-runtimes/<connection-id>`. They are private application data, outside source control, and must remain outside workspace backup archives. Runtime child environments neutralize inherited provider credentials, project configuration and trace exporters. Provider-managed account tokens are never read or copied by Quantix.

## Implemented routes

| --- | --- | --- |
| Codex | Official `openai-codex==0.147.0` and its pinned native runtime; local stdio; managed OpenAI device sign-in, cancellation and logout. | Subscription route only. Read-only sandbox, no shell, unified execution, local image tool, multi-agent tools, memory, connector apps or code mode. Tender reads use MCP. Accounting remains incomplete because the internal inference count is unavailable. |
| Copilot | Official `github-copilot-sdk==1.0.13`; explicit path to the SDK publisher's pinned downloaded runtime; original-client account login or supplied GitHub credential. | Subscription route only. Only MCP tools are available; only the Quantix server's named tools can receive permission. | Claude Agent | Official `claude-agent-sdk==0.2.152` and bundled binary; user API key, optionally an explicitly configured API endpoint. | No Claude account-token authentication. `tools=[]`, strict MCP configuration, empty settings/skills/plugins, explicit permission callback and PreToolUse gate. Maximum turns and output tokens are supplied. Metered execution requires a recorded context window so the whole bounded loop can be reserved. |
| Gemini CLI | Original `@google/gemini-cli@0.58.0`, with its executable resolved from the official npm manifest; headless structured event stream and existing original-client account authentication. | Subscription route only. A deny-all admin policy admits only the Quantix MCP server; core tools, extensions and skills are disabled. Centrally managed settings/policies stop setup rather than being overridden. The current client adapters intentionally do not expose native web tools. A requested web-search route fails before analysis and directs the engineer to an approved model API research connection. No provider switch is implicit.

## Setup and lifecycle

`RuntimeService(repo)` performs no network call or process launch during construction. Its async `status`, `install`, `login` and `logout` methods return the shared RuntimeStatus dictionary; `close` cancels its pending installation/sign-in operations. Status distinguishes package installation, pending sign-in and attended actions. Installation is not described as a successful account/model test.

Its explicit `discover_models` action lists Codex models through the official Python client, Copilot models through its authenticated SDK metadata API, and Claude Agent models through the official Anthropic Models API using BYOK. It creates no analysis session and sends no Tender content. The connection service stores provider provenance with an atomic revision check and preserves manual records. Unknown capabilities remain null; SDK-generated modality defaults are not treated as observed metadata. Copilot's native final-schema support and unreported model limits remain unknown. Runtime web-search support is false because these adapters deliberately expose Tender tools only. Gemini and attended Claude Code return clear manual-entry instructions instead of inventing a catalog. Catalog discovery does not establish successful inference access.

Codex and Claude use the project's pinned bundled SDK builds. The Copilot Install action invokes the publisher's runtime downloader in a dedicated installer child, which downloads and checks the release checksum inside a connection-specific cache. Analysis passes that exact native runtime path to the SDK, avoiding its ambient cache and PATH discovery. The original `@github/copilot@1.0.83` account client is installed separately from the SDK's hostless analysis runtime. No pip installation is attempted by the application.

Gemini and the original Copilot account client use an explicitly selected Node executable, the application's `QUANTIX_NODE_BINARY`, or a managed Node installation. When none exists, Install client downloads Node v24.20.0 LTS from nodejs.org and compares the archive against that release's SHASUMS256.txt. Archive extraction has containment, type and size limits; installation moves a staged directory into place. The npm packages are pinned and their commands are resolved from publisher manifests. An external Gemini entry point must match its supported package manifest. No arbitrary shell arguments, environment dictionaries, binary download URLs or global PATH assumptions are accepted from connection settings.

Attended account windows open only for explicit Login/Logout actions: a native console on Windows, Terminal on macOS, or a detected supported terminal on Linux. Linux can also use an explicit supported terminal_path. macOS/Linux launch a quoted, private script containing only nonsecret home/runtime/display settings and the original account command. The SDK's hostless Copilot runtime is not misrepresented as an interactive login client. Gemini delegates account management to the original client's `/auth` controls. Closing a client window is not interpreted as authentication success. Original attended windows remain under the user's control when Quantix closes.

Frozen application entry points dispatch `runtime-install <node|copilot> <connection-home>` to `ai_runtime_setup.main` before starting the service. Source installations use the same module through Python. Installers perform dependency setup only; they do not sign in or send model requests. Installation and pending managed Codex sign-in hold exclusive connection leases so their configuration cannot change midway.

Runtime budget reservations use the policy's per-request bounds and reserve the entire allowed loop once. Complete token telemetry settles the reservation; missing/interrupted accounting remains uncertain. Codex, Copilot and Gemini metered routes are rejected before content is sent because this adapter does not enforce a hard per-inference metered boundary. Subscription sessions use time, tool-call and, where reported, request-count limits; they are not represented as hard dollar limits. The Codex wrapper does not expose an output-token ceiling, and Gemini's headless adapter does not claim one.

Claude usage is complete only when input/output counts are explicit nonnegative integers and any supplied cache counts are valid; an empty or partial usage object never releases the reserved allowance as zero cost. A runtime Manager reserves its entire configured maximum loop before starting. With the default 12-request run allowance and 12-turn client limit, no allowance remains for an additional specialist consultation in the same run. Increase the approved run request allowance or reduce the client's max_turns when consultation capacity is needed; the reservation is not silently reduced.

Transient connection errors use the explicit RuntimeConnectionFailure category. Configuration, schema, budget, model-reroute and interruption failures remain separate and cannot silently trigger a fallback. Original-client startup is owned as well as the running session. Cleanup retries an unresolved startup for up to five seconds, then uses bounded close/force-close attempts of up to three further seconds. Another cancellation interrupts this cleanup with a one-second final stop attempt. Unconfirmed termination produces a sanitized warning and blocks a successful result or transient fallback; the application does not wait indefinitely for a thread-backed SDK startup.
