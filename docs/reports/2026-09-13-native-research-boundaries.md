# Native research call boundaries

Checked against the installed Pydantic AI 2.40.0 and provider SDK source on 13 September 2026. Verification used synthetic SDK transports and local test records; no live inference or account change was performed.

Google URL Context exists in the portable SDK, but `GoogleModel._get_native_tools` builds an empty `UrlContext` configuration. Its portable fetch count, allowed domains, content-token limit and citation settings are Anthropic-specific and are not transmitted to Google. Google documents supplied public URLs and a twenty-URL request maximum, not the reviewed per-tool/domain controls required by Quantix's general office loop. The descriptor now states this restriction and cites the [Google URL Context documentation](https://ai.google.dev/gemini-api/docs/url-context), separately from the Quantix public URL reader.

Google and xAI native search are blocked before provider-session construction or budget admission because these adapters lack an established enforceable individual-call ceiling. xAI's native web search includes browsing; it is not a separate portable fetch tool. Its documented turn limit can include multiple parallel calls and therefore cannot stand in for a call limit. See [xAI web search](https://docs.x.ai/developers/tools/web-search) and [tool-usage limits](https://docs.x.ai/developers/tools/tool-usage-details). Existing account, model, route and usage records remain readable; execution never switches provider, account or billing automatically.

An engineer can select the shared `fetch_public_url` capability for exact public-page retrieval under the reviewed tool scope and shared research ledger, then cite saved passages. Search discovery requires an explicitly reviewed route whose native adapter enforces its allowance. The descriptor explains both routes without granting either from a capability preview.

OpenAI Responses receives one `max_tool_calls` ceiling across its selected native tools. It is at most `max_native_tool_calls` and, whenever search is selected (including the legacy `web_search` flag), at most `max_search_calls`. The preview displays the effective combined limit. Unexpected reported counts above that limit withhold the response, retain the reservation and block later root admissions through both usage-meter paths. The [Responses API reference](https://developers.openai.com/api/reference/resources/responses/methods/create) documents the native-tool ceiling.

Anthropic native search and fetch expose independent per-tool counters rather than one combined counter. Selecting both in one route is therefore refused; choose one native tool and separately review the shared Quantix URL reader for page access. Quantix does not invent a static split or silently reduce either explicit control.

The focused verification pass covered 88 tests across generation settings, real OpenAI SDK wire requests (code-only and mixed search/code ceilings), negative pre-dispatch checks, overrun retention and subsequent-admission refusal, research routing, plan/delegation review, and budget accuracy. Search-enabled synthetic fixtures now name OpenAI Responses rather than unsupported Chat Completions. The only warning was the upstream Starlette/AnyIO deprecated alias.

A final pass covered generation/native wire and checked-runtime changes: 44 passed immediately; the remaining synthetic Codex case needed its explicit approval rationale in the fixture, then passed on its focused rerun. Both legacy and new Anthropic mixed selections are rejected before execution.
