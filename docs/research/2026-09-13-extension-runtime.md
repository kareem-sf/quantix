# Extension runtime evidence — 13 September 2026

## Official interfaces inspected

The installed official `mcp==2.1.1` SDK was inspected directly, including `mcp.client.stdio.stdio_client`, `StdioServerParameters`, `mcp.client.streamable_http.streamable_http_client`, `ClientSession`, pagination models and server capability discovery. The v2 server entry point is `MCPServer` from `mcp.server.mcpserver`; FastMCP is no longer the current entry point. Streamable HTTP uses the SDK's `httpx2` transport. See the [official Python SDK](https://github.com/modelcontextprotocol/python-sdk) and [MCP transport specification](https://modelcontextprotocol.io/specification/latest/basic/transports).

Production stdio launches only the private Podman command, using a user-selected digest-pinned server image inside the qualified rootless Quantix machine. The command and arguments are inside that image. There is no host-interpreter path, host-folder mount, container socket, inherited provider credential, local trusted-host setting or automatic fallback. It shares Quantix's runtime lifecycle, labels its owned container, has a server-side timeout and explicitly removes the container during cancellation/close. Missing VM/image remains an actionable setup requirement.

Remote connections use the exact configured HTTPS endpoint with certificate verification, no proxy/environment inheritance and no automatic redirects. Optional Bearer credentials are write-only and stored in the OS credential store. Updating a connection advances its revision, atomically swaps the endpoint/configuration and credential reference, removes the old credential, and invalidates the catalog. Credentials cannot move to a changed endpoint through an older connection snapshot. Dynamic OAuth discovery/login is not implemented; the UI exposes only the supported explicit Bearer method.

## Packages and authority

Plugin manifests contain only bounded data, existing checked MCP connection selections and existing immutable `SkillPackageService` package IDs. Unknown fields/install hooks are rejected. No second skill archive or installation-hook system was introduced. Inspection creates a fingerprint of manifest, exact connection revisions/catalogs and linked skill hashes. Install, enable, disable, update by new immutable version, rollback and remove are separate actions. These actions alone never grant a Tender capability.

`ReviewedExtension` pins package ID/hash, connection ID/revision, destination, full catalog hash and selected tools/resources/prompts. The fixed wrappers are `discover_extensions`, `call_extension`, `read_extension_resource` and `get_extension_prompt`. Each execution checks the actual active Manager/staff scope, exact reviewed extension and live package/connection state. It reopens an official SDK session and compares the complete current catalog before dispatch. Remote names never become Quantix authority keys. Results and prompt text remain untrusted data and never mark Tender sources inspected.

External requests keep durable invocation receipts. Replaying the same identity returns the saved receipt; changed arguments conflict. A dropped/stopped request remains uncertain when its effect cannot be confirmed and is not automatically retried. Connection changes, disabled packages, changed schemas and superseded work reject execution or publication. Local JSON Schema validation is bounded; external schema references and regular-expression schemas are refused rather than fetched/executed on the host.

Declared scripts require the exact reviewed loaded package, explicit `execute_skill_script` capability, a declared member and exactly one supported runtime requirement (`monty: 0.0.23` or `python: 3.12`). The normal `OfficeContext` source fence supplies only selected JSON source windows and records their actual reads. Runtime/source/account/method applicability are rechecked before dispatch and publication. Input-schema checks, exact package/script hashes and idempotent execution receipts are retained. Script packages cannot use a host-subprocess fallback.

## Independent boundary-review fixes

MCP effects and charges now default to unknown. An authenticated engineer must save exact per-capability effect/billing declarations and documentation; remote execution admits only supported read operations with known unmetered use, while qualified network-denied local containers may also produce local drafts. Contradictory server hints, commercial/mutation verbs, unknown effects and metered/unknown billing remain blocked. These declarations and capability-call/response limits are pinned in package and Tender scope. Server hints alone grant nothing.

Logical operation receipts now bind the exact connection, destination, capability and arguments independently of provider IDs. Matching uncertain outcomes block fresh IDs and new/resumed roots until explicit engineer reconciliation; legacy uncertain records remain guarded. Saved results are marked as replays. The receipt history, safe recorded arguments, Tender identity and reconciliation controls are available in extension settings. Exact Bearer credentials are scrubbed from nested server catalog/results before hashing, persistence or model delivery; an actual authenticated TLS echo regression verified the boundary.

Progressive discovery exposes one selected capability's schema, description or prompt arguments after current grant/catalog checks. Declared scripts and standalone `execute_tool_code` / `execute_python_analysis` require the exact reviewed runtime/binary/image/library fingerprint and server-held limits. Their callbacks intersect the live root/binding tools with declared requirements and exclude recursive interpreter/script entry points. JSON decoding happens inside the shared nested result fence before source-read commit. The approved-script regression computes two actual saved values and combines 42 + 5 = 47 through structured callback results; its replay does not duplicate calculations.

Runtime leases now count nesting and block maintenance for all active operations. New operations are refused during maintenance. Failed subprocess cleanup kills the owned process group/job even after its parent exits and bounds final drain/reap. An exited-parent/live-descendant regression and actual Monty read-rollback regression passed.

## Public browser boundary

The public reader now shares the private runtime's connection, maintenance lease, bounded command owner and cleanup. A disposable Chromium container has no network interfaces except loopback and mounts only a per-request proxy socket volume read-only. A separate trusted proxy process accepts only GET/HEAD to the checked scheme, hostname, port and pinned public IPv4 address; it forwards no account credentials or cookies. Cross-scheme/host/port redirects, private targets, POST and WebSocket requests are refused. Page JavaScript has no direct TCP/UDP route to bypass the gateway. This is the isolation boundary; browser request interception is additional filtering.

The Playwright 1.63.0 base is pinned to the inspected MCR digest `sha256:eff16c30e6f3f4af0a03fa4b706120d5e9b0891c344a27d64559aff5900a4a27`, and package installation uses its committed lock. Setup pins the built image ID and hashes the container assets plus host command, resource-limit and process-owner implementations. It must pass an actual VM probe of network denial, proxy rejections, read-only mounts, user/capabilities, memory/process/CPU limits and Chromium execution before recording qualification. It must also obtain a nonempty 200 response from `https://example.com/` through the allowed gateway with normal TLS certificate verification. Strict manifest/proof validation checks every required probe, the exact base and a recomputed fingerprint; missing fields or source changes invalidate readiness. Each page receipt retains the exact image/fingerprint and observed HTTP status. Both containers and their socket volume are removed before the operation lease ends.

Eight private-runtime adapter/manifest tests and three Node proxy-policy tests passed after the final review fixes. These injected unit fixtures do not establish OS or container qualification. This reader currently supports anonymous, same-scheme/host/port public IPv4 pages; IPv6-only sites and redirects that change scheme or port are unavailable.
